# 無料で作る方針（v1.0）

更新日: 2026-08-08
前提: **費用ゼロ**。Apple Developer Program の年 $99 は払わない。

---

## 1. まず結論

**PWA（ホーム画面に追加するWebアプリ）で作ります。**

「お金を使わない」という制約を入れた瞬間、iPhone にネイティブアプリを入れる正規ルートは
ほぼ全滅します。残る現実的な道は PWA だけです。

そして調べた結果、**PWA でも要件のほぼ全部が実装できます**。
妥協が必要なのは「就寝時の運用」の部分だけです。

---

## 2. なぜ他の道が消えるのか

| 方法 | 費用 | Windowsで可能か | 判定 |
|---|---|---|---|
| EAS Build / Xcode で実機インストール | **$99/年** | ○ | ❌ 費用が発生 |
| 無料 Apple ID + Xcode 署名 | 無料 | **✗ Macが必須** | ❌ Macが無い |
| GitHub Actions + AltStore サイドロード | 無料 | △ | ⚠️ 後述 |
| **PWA（ホーム画面に追加）** | **無料** | **○** | ✅ **これで行く** |

### AltStore ルートについて（一応の選択肢として）

GitHub Actions の macOS ランナー（パブリックリポジトリなら無料）で署名なしIPAをビルドし、
Windows版 AltServer で自分の Apple ID を使ってサイドロードする、という道は理論上あります。

- **良い点**: 無料でネイティブアプリが動く。信頼性は最高
- **悪い点**:
  - セットアップが極めて煩雑（CI設定、証明書、AltServer常駐）
  - 無料 Apple ID の署名は **7日で失効**。AltServer が同じWi-Fi上にいる時に自動再署名するが、
    PCを起動していない週があると**アラームが動かなくなる**
  - 目覚ましで「今週は署名が切れてました」は致命的

→ **却下**。最初からこれをやるのは無謀です。PWA で価値を確認してからでも遅くない。

## 3. PWA で「できること」と「できないこと」

### ✅ できること（要件のほぼ全部）

| 要件 | PWAでの実現方法 |
|---|---|
| 指定時刻に鳴る | 画面を点けたまま `setInterval` で時刻監視 → Web Audio で再生 |
| **タスクを完了するまで止まらない** | JSで制御するので**完全に実装できる**。停止ボタンを置かなければいいだけ |
| **スヌーズを押しても短時間で再発火** | タイマーで再鳴動。**回数カウントも正確に取れる** |
| カメラで撮影 | `getUserMedia`（HTTPS必須。無料ホスティングでOK） |
| 日付のOCR判定 | **Tesseract.js**（完全ブラウザ内・無料・初回以降オフライン可） |
| 起床ログの保存 | IndexedDB（Dexie）。travel-planner と同じ |
| カレンダー画面 | 普通にReactで作る。**むしろネイティブより楽** |
| ホーム画面アイコン | manifest.json で通常のアプリのように見える |

### ❌ できないこと（正直に）

| 制約 | 内容 | 回避策 |
|---|---|---|
| **バックグラウンド発火不可** | 画面を消す・他アプリを開くとタイマーが止まる | **就寝時にアプリを開いたまま、充電しながら枕元に置く**運用にする |
| **消音スイッチを突破できない** | iOSの消音スイッチがオンだと音が出ない | 就寝前にオフにする（＝着信音オン）。Webからは変更不可 |
| **システム音量を制御できない** | 音量が小さいと小さいまま鳴る | 就寝前に音量を上げる運用 |
| 万一のクラッシュ | Safariが落ちたら鳴らない | **純正の時計アプリでも同時刻にアラームをセットしておく**（保険） |

### 運用のかたち

```
就寝前:
  1. 消音スイッチをオフ、音量を上げる
  2. 充電ケーブルを挿す
  3. アプリを開いて起床時刻をセット →「セット」をタップ
     （このタップが重要。iOSは操作起点でないと後から音を鳴らせない）
  4. 画面が暗い時計表示になる。そのまま枕元に置く（Wake Lockで画面は消えない）
  5. ★保険として純正アラームも同時刻にセット

起床:
  6. 爆音が鳴る。停止ボタンは無い
  7. 「タスクを開始」→ カメラ起動
  8. 今日の日付が書かれたものを撮影 → OCR判定
  9. 合格 → 音が止まり、カレンダー画面へ
```

> 「充電しながら枕元に置く」は**目覚まし時計として全く自然な運用**です。
> むしろ普通のスマホアラームと同じなので、実用上の障害は小さいと判断しました。

## 4. 技術スタック（無料版）

```
Vite + React + TypeScript          … 既存スキルそのまま
├─ Web Audio API                   … アラーム音を合成（音源ファイル不要）
├─ Screen Wake Lock API            … 画面を消させない（iOS 16.4+ 対応）
├─ getUserMedia                    … カメラ
├─ tesseract.js                    … ブラウザ内OCR
├─ dexie                           … IndexedDB。travel-planner と同じ
├─ vite-plugin-pwa                 … manifest + Service Worker（オフライン化）
└─ Cloudflare Pages / Vercel       … 無料HTTPSホスティング
```

**Next.js ではなく Vite にした理由**: サーバー機能が一切不要な純クライアントアプリなので、
Next.js は重すぎる。ただし travel-planner と揃えたいなら Next.js の静的エクスポートでも同じことができる。
**ここは好みで選んで問題ない**。

### OCRの言語設定について（重要なトレードオフ）

Tesseract.js の日本語モデル（`jpn`）は**十数MBあり、読み込みが遅く精度も不安定**です。
一方 `eng` + 文字ホワイトリスト（数字と `/-.` のみ）に絞ると、**軽くて速くて精度が高い**。

→ **`eng` + 数字ホワイトリスト**を採用します。
その代わり、判定できる形式が `2026/08/08` のような**数字形式に限定**されます。

これは運用でカバーできます:

> **前夜に紙へ「2026/08/08」と手書きして洗面所に貼っておく。**

この方式には副次的な利点があります:
- 毎日レシートを用意する必要がない（入手性の問題が消える）
- 前夜に書く行為が就寝儀式になる
- 朝は必ず洗面所まで歩かされる（＝本来の目的である覚醒に直結）
- 太い字で大きく書けるので**OCR精度が跳ね上がる**

レシートも「日付が数字形式で印字されていれば」そのまま使えます。

## 5. 段階的な進め方

| Phase | 内容 | 所要 | 得られるもの |
|---|---|---|---|
| **0** | ブラウザで音が鳴るか、Wake Lockが効くか、OCRが日付を読めるかを個別に確認 | 半日 | 技術的な地雷の早期発見 |
| **1** | 最小フロー: 時刻セット→鳴る→撮影→判定→止まる | 2〜3日 | **明日の朝から実戦投入できる** |
| **2** | ログ保存とカレンダー画面、スヌーズ回数の表示 | 2日 | 振り返りの楽しさ |
| **3** | PWA化（オフライン動作、ホーム画面アイコン）、UI調整 | 1日 | 完成度 |

> **Phase 1 の時点で一度必ず実際に使ってみること。**
> 「日付を撮影して起きる」が自分に本当に効くかを、作り込む前に確かめる。

### もし将来ネイティブにしたくなったら

PWA を使ってみて「これは価値がある」と確信できたら、その時点で $99 を払って
Expo でネイティブ化する道が残っています。その際:
- **日付照合ロジック（`dateOcr.ts` の純粋関数部分）はそのまま移植できます**
- 画面の構成やUXの知見もそのまま活きます
- 退避してある `docs/archive-expo/` のコードが出発点になります

**先に無料で価値を確かめてから課金する**、という順番が合理的です。
